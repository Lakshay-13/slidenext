PRACTICE STANDARDS // DISCUSS

Code of Conduct: Good vs. Bad Practices

Let's discuss how to align our habits to avoid security drifts and prompt loops.

check_circle Good Practices
add

Be Clear & Concise in Prompts

Provide explicit steps, expected variables, output templates, and file schemes upfront.

add

Overlook & Verify Code Manually

Verify git diff changes manually. Never push unchecked changes to feature branches.

add

Use Available Tools Correctly (MCP/Plugins)

Utilize contextual directory access plugins or MCP servers (e.g. database schema check, git history search).

cancel Bad Practices
close

Avoid Random / Vague Instructions

Don't say "fix this" or "rewrite the file" without specifying context bounds and schemas.

close

Never Grant Full Unrestricted Access

Restrict write bounds, review console commands before approval, and never run blind curl commands.

close

Don't Drag on Endless Prompt Sessions

Long chat logs bloat context tokens and lead to model confusion. Fresh prompts yield cleaner fixes.
